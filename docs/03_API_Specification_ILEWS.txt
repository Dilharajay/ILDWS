1. API OVERVIEW
----------------

The ILEWS RESTful API provides programmatic access to all system data and
control functions. It is built on FastAPI (Python) and follows REST principles
with JSON request/response bodies. All endpoints are versioned under /v1.

Design Principles:
  - Stateless: No server-side session state; all auth via bearer token.
  - Idempotent: PUT and DELETE operations are idempotent.
  - Consistent: Unified envelope format for all responses.
  - Secure: All endpoints require authentication; role-based access enforced.
  - Auditable: All write operations logged with actor identity.

API Environments:
  Production : https://api.ilews.gov/v1
  Staging    : https://staging-api.ilews.gov/v1
  Development: http://localhost:8000/v1


2. AUTHENTICATION
------------------

2.1 Obtaining a Token

    POST /v1/auth/token

    Request Body (application/x-www-form-urlencoded):
      grant_type : "password"
      username   : <user email>
      password   : <password>
      client_id  : "ilews-web"

    Response (200 OK):
      {
        "access_token": "eyJhbGciOiJSUzI1NiIsIn...",
        "token_type": "bearer",
        "expires_in": 28800,
        "refresh_token": "dGhpcyBpcyBhIHJlZnJlc2...",
        "scope": "openid profile"
      }

2.2 Using the Token
    Include in all requests as an HTTP header:
      Authorization: Bearer <access_token>

2.3 Token Refresh
    POST /v1/auth/refresh
    Body: { "refresh_token": "<refresh_token>" }
    Returns: New access_token and refresh_token pair.

2.4 Token Expiry
    Access tokens expire after 8 hours of inactivity.
    Refresh tokens expire after 30 days.

3. COMMON RESPONSE FORMATS
---------------------------

3.1 Success Response Envelope
    All successful responses return the following structure:
    {
      "status": "success",
      "data": { ... },       -- Requested data object or array
      "meta": {              -- Pagination and request metadata (if applicable)
        "page": 1,
        "per_page": 50,
        "total": 243,
        "total_pages": 5
      },
      "timestamp": "2026-02-28T08:30:00Z"
    }

3.2 Error Response Envelope
    {
      "status": "error",
      "error": {
        "code": "ERR_NODE_NOT_FOUND",
        "message": "Sensor node with ID 'X99' does not exist.",
        "details": { ... }   -- Optional additional context
      },
      "timestamp": "2026-02-28T08:30:00Z"
    }

3.3 Pagination
    List endpoints support query parameters:
      ?page=1&per_page=50
    Default: page=1, per_page=50. Maximum: per_page=500.

5. SENSOR NODES API
--------------------

5.1 List All Nodes

    GET /v1/nodes
    Description: Returns all registered sensor nodes.
    Auth Required: YES | Min Role: Read-Only

    Query Parameters:
      slope_id   (string, optional) -- Filter by slope
      status     (string, optional) -- Filter by: active, inactive, error
      page, per_page

    Response 200:
    {
      "status": "success",
      "data": [
        {
          "node_id": "A1",
          "slope_id": "SLOPE_BKT_01",
          "name": "Node Alpha-1",
          "latitude": 3.1520,
          "longitude": 101.7120,
          "depth_config": [0.5, 1.0, 2.0],
          "status": "active",
          "last_seen": "2026-02-28T08:25:00Z",
          "battery_voltage": 12.4,
          "firmware_version": "1.3.2",
          "installed_date": "2025-06-15"
        }
      ],
      "meta": { "page": 1, "per_page": 50, "total": 12, "total_pages": 1 }
    }

5.2 Get Single Node

    GET /v1/nodes/{node_id}
    Auth Required: YES | Min Role: Read-Only

    Path Parameter:
      node_id (string) -- e.g., "A1"

    Response 200:
    { "status": "success", "data": { <node_object> } }

    Response 404:
    { "status": "error", "error": { "code": "ERR_NODE_NOT_FOUND", ... } }

5.3 Register New Node

    POST /v1/nodes
    Auth Required: YES | Min Role: System Admin
    Description: Registers a new sensor node. Manual coordinate input required.

    Request Body:
    {
      "node_id":        "A5",
      "slope_id":       "SLOPE_BKT_01",
      "name":           "Node Alpha-5",
      "latitude":       3.1535,
      "longitude":      101.7145,
      "depth_config":   [0.5, 1.0, 2.0],
      "installed_date": "2026-02-28"
    }

    Validation Rules:
      - node_id: unique, 2-8 chars, alphanumeric + hyphen
      - slope_id: must reference existing slope
      - latitude: -90.0 to 90.0
      - longitude: -180.0 to 180.0
      - depth_config: array of 1-5 float values (metres)

    Response 201:
    { "status": "success", "data": { <created_node_object> } }

5.4 Update Node

    PUT /v1/nodes/{node_id}
    Auth Required: YES | Min Role: System Admin
    Description: Updates node metadata (coordinates, name, status).

    Request Body: (all fields optional, partial update supported)
    {
      "name":      "Node Alpha-5 Updated",
      "latitude":  3.1536,
      "longitude": 101.7146,
      "status":    "inactive"
    }

    Response 200: { "status": "success", "data": { <updated_node_object> } }

5.5 Delete Node

    DELETE /v1/nodes/{node_id}
    Auth Required: YES | Min Role: System Admin
    Note: Soft delete only. Historical data is retained. Node removed from map.

    Response 200: { "status": "success", "data": { "deleted": true } }

        "accel_x_ms2": 0.02,
        "accel_y_ms2": 0.01,
        "accel_z_ms2": 9.81,
        "vibration_hz": 12.5,
        "battery_voltage": 12.4,
        "rssi_dbm": -85,
        "data_quality": "valid"
      }
    }

6.2 Get Historical Readings

    GET /v1/nodes/{node_id}/readings
    Auth Required: YES | Min Role: Read-Only

    Query Parameters:
      start_time (ISO 8601, required) -- e.g., 2026-02-27T00:00:00Z
      end_time   (ISO 8601, required) -- e.g., 2026-02-28T00:00:00Z
      resample   (string, optional)   -- "raw", "1min", "15min", "1h"
                                         Default: "raw"
      page, per_page

    Response 200:
    {
      "status": "success",
      "data": [
        { <reading_object_1> },
        { <reading_object_2> },
        ...
      ],
      "meta": { ... }
    }

6.3 Export Readings

    GET /v1/nodes/{node_id}/readings/export
    Auth Required: YES | Min Role: Operator
    Description: Returns time-series data as downloadable file.

    Query Parameters:
      start_time (required)
      end_time   (required)
      format     (string) -- "csv" or "json". Default: "csv"

    Response: File download (Content-Disposition: attachment)
    Content-Type: text/csv OR application/json

6.4 Get Readings for Entire Slope

    GET /v1/slopes/{slope_id}/readings/latest
    Auth Required: YES | Min Role: Read-Only
    Description: Returns latest reading from all nodes on a slope.

    Response: Array of latest reading objects, one per node.

13. WEBSOCKET API
------------------

13.1 Overview
    The dashboard connects to a WebSocket endpoint for real-time data streaming.
    Server pushes events to connected clients without polling.

    Endpoint: wss://api.ilews.gov/v1/ws
    Auth: Pass bearer token as query param on connect:
          wss://api.ilews.gov/v1/ws?token=<access_token>

13.2 Event Types (Server → Client)

    a. RISK_UPDATE: Risk level change for a slope
       {
         "event": "RISK_UPDATE",
         "data": {
           "slope_id":   "SLOPE_BKT_01",
           "risk_level": "RED",
           "risk_score": 0.91,
           "timestamp":  "2026-02-28T07:45:00Z"
         }
       }

    b. NEW_READING: New sensor reading arrived (selected nodes only)
       {
         "event": "NEW_READING",
         "data": { <reading_object> }
       }

    c. ALERT_TRIGGERED: New alert created
       {
         "event": "ALERT_TRIGGERED",
         "data": { <alert_object> }
       }

    d. NODE_STATUS_CHANGE: Node went offline or came back online
       {
         "event": "NODE_STATUS_CHANGE",
         "data": {

14. RATE LIMITS
----------------

Rate limits are applied per authenticated user (by user_id from JWT).

+------------------------------+------------------+
| Endpoint Group               | Rate Limit       |
+------------------------------+------------------+
| Authentication endpoints     | 10 req/min       |
| Read endpoints (GET)         | 300 req/min      |
| Write endpoints (POST/PUT)   | 60 req/min       |
| Export endpoints             | 5 req/min        |
| Report generation            | 10 req/hour      |
| WebSocket connections        | 5 concurrent/user|
+------------------------------+------------------+

Rate limit headers returned on all responses:
  X-RateLimit-Limit:     300
  X-RateLimit-Remaining: 247
  X-RateLimit-Reset:     1709111460    (Unix timestamp of window reset)

When rate limit exceeded:
  HTTP 429 Too Many Requests
  { "status": "error", "error": { "code": "ERR_RATE_LIMIT",
    "message": "Rate limit exceeded. Try again in 43 seconds." } }
